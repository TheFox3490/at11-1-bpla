# 1.5 Техническое задание

## Назначение

Прототип информационно-управляющей системы из двух БПЛА: разведчик строит
карту участков, компьютер проверяет её и формирует задание, исполнитель
выполняет условную операцию (световой индикатор 2 с) в разрешённых точках и
подтверждает результат.

## Классы объектов

| Класс | Смысл | Действие |
|---|---|---|
| A | операция назначена | может быть целью, если проходит все проверки |
| B | только наблюдение | в миссию не попадает |
| U | класс не определён | в миссию не попадает; противоречивые наблюдения сводятся в U |

Класс кодируется цветом **и** формой, чтобы распознавание было устойчивым и
объяснимым без нейросети.

## Точность

| Требование | Значение |
|---|---|
| ошибка положения цели | ≤ 0,07 м (предел 0,13 м по бюджету) |
| ошибка исполнителя | 0,06 м |
| взаимная привязка | 0,02 м |
| радиус воздействия | 0,04 м |
| рабочая область | 0,25 м |
| калибровка: худшая контрольная точка | ≤ 30 мм, иначе повтор разведки |

## Формат карты

JSON, система координат F, единицы «м»:

* заголовок: `mission_id`, `coordinate_frame`, `units`, `created_at`,
  `valid_until`, `calibration_version`, `checksum`;
* `targets`: `target_id`, `action_id`, `klass`, `point{x,y}`,
  `position_error_m`, `priority`, `source_object_id`, `source_frames`;
* `forbidden`: полигоны зон;
* `rejected`: отклонённые объекты с причинами;
* `budget_s`, `partial`, `skipped` — бюджет и причины пропусков.

Карта наблюдений (`observation_map.json`) содержит все объекты, карта-задание
(`missions/*.json`) — только допустимые A. Это разные документы.

## Время жизни

15 минут после последнего использованного кадра разведки. Проверяется перед
стартом и перед каждой операцией. При недоступной общей шкале времени
(нет корректных меток) карта отвергается. Контрольная сумма выявляет
повреждение файла, но не заменяет проверку смысла.

## Критерий разрешения операции

Операция разрешена, только если одновременно:

1. карта валидна и не просрочена;
2. цель класса A и вне расширенной запретной зоны;
3. дрон в радиусе 0,25 м от цели, высота 1,0–1,4 м;
4. устойчивое положение в области ≥ 1 с;
5. бюджет точности выполняется;
6. действие ещё не подтверждено (нет дубля);
7. локализация свежая (≤ 0,3 с) и канал управления доступен.

LED включается на 2 с и выключается при нарушении любого условия. Успех —
только 2 с непрерывного разрешённого действия.

## Запретные зоны

Полигоны в F. Маршрут не пересекает расширенный на 0,23 м контур. Полёт
через реальную зону недопустим; при входе — прекращение операции и аварийная
посадка. Цель внутри расширенной зоны исключается из миссии.

## Поведение при отказах

| Ситуация | Поведение |
|---|---|
| не хватает времени на все цели | подмножество по приоритету, причины пропусков в файле и отчёте, возврат |
| бюджет исчерпан в полёте | LED off, возврат на базу, посадка |
| карта просрочена до старта | отказ, дрон не взлетает |
| карта просрочена в полёте | запрет новых операций, немедленный возврат |
| потеря данных/связи | LED off, автономный возврат или аварийная посадка |
| дубликат команды | повторное воздействие запрещено, статус `duplicate_action_blocked` |
| потеря подтверждения после включения | запись остаётся `uncertain`, повтор не выполняется, цель помечается «до проверки» |
| противоречивые кадры | объект `U`, в миссию не попадает |
| ошибка координат выше бюджета | цель пропускается, при систематике — повторная разведка |

## Порядок подтверждения

1. команда на включение (`led_command`) пишется отдельно;
2. фактическое включение (`led_confirmed`) — после 2 с;
3. запись в долговечный реестр действий;
4. сводка исполнения и журнал с координатами, возрастом измерения, оценкой
   ошибки и причиной остановки.

## Критерии приёмки

* разведка: 25 кадров, посадка, карта наблюдений из 10 объектов;
* карта-задание: 6 допустимых A, 4 отклонённых с причинами;
* исполнитель: 6/6 подтверждено, посадка, повторный запуск — 0 подтверждений;
* сценарии C1–C8 — PASS в протоколе стенда;
* отсутствие действий по сомнительным координатам.

## Минимум и желательная полнота

**Минимальное безопасное поведение:** не выполнять операцию при сомнительной
карте, не повторять воздействие, не входить в запретную зону, завершать
миссию посадкой, вести журнал. Необработанная сомнительная цель
предпочтительнее ошибочного воздействия.

**Желательная полнота:** выполнить все допустимые цели в бюджете, показать
сравнение методов маршрута, объяснить каждый пропуск, дать оператору
приоритеты и пересчёт.

## Риски и меры защиты

| Риск | Мера |
|---|---|
| повреждение файла миссии | checksum + повторная проверка смысла |
| устаревшая карта | TTL до старта и на каждой операции |
| ошибка калибровки | независимые контрольные точки + порог 30 мм |
| вход в запретную зону | расширение 0,23 м, проверка каждого отрезка и шага |
| повторное воздействие | долговечный реестр действий, `uncertain` блокирует повтор |
| потеря локализации/связи | LED off, возврат/посадка, журнал |
| ручной ввод координат | исключён: режим 2 меняет только полигон |
