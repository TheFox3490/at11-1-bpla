# 1.2 Архитектура взаимодействия

## Сравнение вариантов

| Вариант | Плюсы | Минусы | Когда уместен |
|---|---|---|---|
| Сплошная операция одним БПЛА | простой регламент, не нужна карта и валидатор, нет межролевых ошибок | расход препарата на всей площади, нет адресности и подтверждения по цели | низкая доля целевых участков не важна, обработка дешевле стоимости обследования |
| Один универсальный БПЛА в двух ролях | один аппарат, одна команда, проще логистика | последовательные вылеты всё равно нужны; смена нагрузки и калибровки; хуже разделение ответственности | резервный организационный вариант, малые площади |
| Разделение ролей (разведчик + исполнитель) | адресная операция, проверяемая карта, отдельные калибровки, понятная ответственность | два аппарата, передача файла, нужен валидатор и защита от дублей | основная схема проекта |

## Схема обмена

```
разведчик ── кадры + локальные позы + калибровочный кадр ──► компьютер
                                                              │
                                                   CV: калибровка L→F
                                                   детекция и объединение
                                                              │
                                                   карта наблюдений (все объекты)
                                                              │
                                                   валидатор карты/задания
                                                              │
                                                   планировщик (2 метода, бюджет)
                                                              │
                                                   файл миссии (F, JSON + checksum)
                                                              │
                                                              ▼
исполнитель ◄── файл миссии ── проверка TTL, классов, зон, checksum
     │
     ├─ полёт по маршруту в своей локальной системе L_exec
     ├─ стабилизация 1 с, шлюз допуска, LED 2 с
     ├─ защита от повторного воздействия (реестр действий)
     └─ журнал + сводка ──► отчёт и протокол испытаний
```

## Что исполняется на борту, а что на компьютере

| Борт | Компьютер управления |
|---|---|
| удержание высоты и стабилизация | калибровка камеры и перевод L→F |
| проверка шлюза допуска перед включением | детекция, классификация, объединение наблюдений |
| включение/выключение LED и контроль 2 с | построение карты задания и её валидация |
| геозона: прекращение операции при входе в NFZ | планирование маршрута, бюджет времени, приоритеты |
| аварийное завершение при потере локализации/связи | срок действия карты, контрольная сумма, журнал миссии |
| запись телеметрии | формирование отчёта и протокола испытаний |

## Ограничения, заложенные в проект

* **Передача файла допустима, ручное внесение координат целей после
  разведки — нет.** Поэтому режим 2 редактирует только полигон поля: он
  меняет то, что увидит камера, а координаты целей по-прежнему вычисляет CV
  из кадров. Ручная «учебная миссия» помечена как тренировка.
* **Два последовательных вылета обязательны**: разведка ≤ 6 мин, исполнение
  ≤ 6 мин, обработка между ними ≤ 3 мин.
* Локальные системы координат не считаются совпадающими с F: у разведчика
  `L_recon` (начало 0.20/0.30 м, курс +7°), у исполнителя `L_exec`
  (5.55/3.70 м, курс −160°). Привязка к F получается калибровкой и
  пересчётом, а не предположением.
* Исполнитель получает только файл миссии. Эталонные координаты из
  материалов жюри в конвейер не передаются.
