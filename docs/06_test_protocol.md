# Часть Б: протокол испытаний, показатели и подготовка к финалу

Актуальный протокол генерируется стендом:

```
F9 в приложении            — оверлей «ИСПЫТАНИЯ C1–C8», кнопка у каждого сценария
python app.py --tests      — прогон всех сценариев без кликов
python app.py --tests --only C3,C6
```

Результаты: `runs/tests/<bench_id>/`

```
protocol.md          таблица «ожидалось / получено / задержка / PASS-FAIL / доказательство»
protocol.json        то же машинно-читаемо
map_C*.png           карта поля: объекты, NFZ+0.23, маршрут, пропуски, точка прерывания
timeline_C*.png      таймлайн исполнителя (стабилизация, LED, прерывание, посадка)
shots/*.png          снимок экрана в момент проверки
<миссия>.json        входные файлы сценариев (см/неизвестная калибровка, TTL и т.д.)
```

Стенд воспроизводит испытания на **реальном поле приложения**: тот же дрон,
тот же маршрут, та же сцена. Сценарии идут на ускорении ×5, операторское поле
на время прогона подменяется базовой раскладкой задания и восстанавливается
после.

## Б1. Сценарии C1–C8

| № | Сценарий | Ожидалось | Получено (прогон 2026-11-18) | Задержка | Результат |
|---|---|---|---|---|---|
| C1 | два разных локальных начала | корректный перевод в F, исполнение только A | начала разные; оценка L_recon→F: масштаб 0.995, курс 7.00°; 6/6 подтверждено | 21 с | PASS |
| C2 | см вместо м / неизвестная калибровка | отказ до взлёта без автокоррекции | `units_must_be_m`, `unknown_calibration_version`, дрон на HOME, файл не изменён | 0.3 с | PASS |
| C3 | просрочка карты | запрет операций, безопасное завершение | до старта отказ; в полёте через 13.4 с прервано (`map_expired_or_invalid`), посадка 0.06 м | 3 с | PASS |
| C4 | цель в NFZ / путь через зону | исключение цели или обход | 2 A в NFZ исключены, маршрут вне NFZ+0.23 | 0.1 с | PASS |
| C5 | повтор задания / потеря подтверждения | нет повторного воздействия | повтор заблокирован, LED не включался, `uncertain` без повтора | 1.8 с | PASS |
| C6 | потеря локализации > 0.3 с / связи | LED off, штатное аварийное завершение | аварийная посадка на месте; при потере связи — возврат и посадка | 2.5 с | PASS |
| C7 | ошибка выше допустимой / противоречия | пропуск сомнительной цели | противоречие → U и пропуск; ошибка 0.14 м → пропуск; калибровка 85 мм отклонена | 0.2 с | PASS |
| C8 | нехватка времени | подмножество, причины, возврат | подмножество 3/6 с причинами; исполнитель прервался по бюджету и вернулся | 2.6 с | PASS |

Как проверяется C5 отдельно: реестр действий перечитывается с диска новым
экземпляром исполнителя — это эквивалент перезапуска приложения. Повтор файла
даёт `duplicate_action_blocked`, команда LED не формируется. Запись
`uncertain`, оставшаяся после «падения» на включении, блокирует повтор и
помечается в отчёте как «до проверки».

Средняя и максимальная ошибки указаны отдельно: средняя скрывает выбросы,

обработкой карты; переход между ролями — это посадка разведчика, запуск CV и
подготовка исполнителя, они входят в интервал между вылетами (≤ 3 мин).

Карты разведки, маршрут и фактические места включения: `map_C1.png` и
`map_C8.png` в каталоге прогона; точки LED отмечены кольцами на 3D-поле, а в
2D-карте — номерами целей и маршрутом.

## Б3. Подготовка к финалу

### Запуск

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt

.\.venv\Scripts\python app.py            # приложение, 3 режима
.\.venv\Scripts\python app.py --tests    # протокол C1–C8
.\.venv\Scripts\python app.py --selftest # быстрый регресс приложения
.\.venv\Scripts\python sim\demo.py --selftest  # регресс исходной демо-сцены
.\.venv\Scripts\python -m pytest tests -q      # быстрые проверки без окна
```

### Схема интерфейсов

| Интерфейс | Формат | Кто пишет | Кто читает |
|---|---|---|---|
| кадры разведки | PNG 640×480 + JSON (поза L, sha256, время) | разведчик | CV |
| карта наблюдений | JSON (все объекты) | CV | оператор, отчёт |
| карта-задание | JSON + checksum (только A) | CV/планировщик | исполнитель |
| журнал | JSONL (события, t, координаты, возраст, причина) | исполнитель | протокол, разбор |
| реестр действий | JSON `action_id → статус` | исполнитель | следующий запуск |
| протокол испытаний | MD + JSON | стенд | жюри |

### План калибровки

1. Разложить 4 маркера и 2 контрольные точки по схеме поля.
2. Снять калибровочный кадр с высоты 1.2 м в надир.
3. Построить преобразование L→F по 4 маркерам.
4. Проверить 2 независимые точки: допуск 30 мм, иначе повтор.
5. Зафиксировать `calibration_version` в миссии; исполнитель отвергает
   неизвестную версию.

### Предполётные проверки

- [ ] полезная нагрузка при включении питания **выключена** (LED не горит);
- [ ] поле и маркеры соответствуют раскладке, зона калибровки свободна;
- [ ] зона NFZ нанесена и совпадает с полигоном в миссии;
- [ ] `state/action_registry.json` проверен: нет необъяснимых `uncertain`;
- [ ] системное время компьютера корректно (иначе карта отвергается);
- [ ] заряд аккумуляторов разведчика и исполнителя;
- [ ] оператор знает порядок: F9 — стенд, 1 — разведка, 2 — исполнитель,
      «Сброс сценария» не стирает реестр.

### Разрешённые действия оператора

Разрешено: запуск/остановка сценария, выбор сцены и темпа, применение
полигона поля в режиме 2, выбор бюджета времени и приоритетов **после**
разведки, пересчёт маршрута, запуск исполнителя для валидной миссии, просмотр
журнала и протокола.

Запрещено: вводить координаты целей вручную после разведки, править файл
миссии, отключать проверки, повторно запускать подтверждённые действия,
взлетать при невалидной карте.
